# 项目定义

## 一、业务背景

项目模拟电商平台经营分析团队的工作。管理层希望系统性了解平台增长、用户价值、
商品结构、商家表现和履约体验；分析师还希望通过自然语言缩短常规取数时间。

## 二、项目目标

1. 建立可复用且口径明确的电商经营指标体系。
2. 通过 SQL 和 Python 找出影响增长与体验的关键因素。
3. 输出有证据支撑、可以落地的业务建议。
4. 构建基于指标语义层的分析 Copilot。
5. 通过标准问题集评估 Copilot 的准确性，而非只展示成功案例。

## 三、核心分析问题

### 经营表现

- GMV、有效订单量和客单价如何变化？
- 增长或下降主要由哪些品类、州和商家贡献？
- 是否存在显著的周期性或异常月份？

### 用户价值

- 新老客户的规模、消费和复购表现有何差异？
- 不同首购月份的客户后续留存和复购表现如何？
- RFM 分层下，哪些群体需要重点维护或召回？

### 商品与商家

- 哪些品类贡献主要收入，哪些属于高增长或长尾品类？
- 平台是否过度依赖少数商家？
- 商家履约时效和评价之间有何关系？

### 履约体验

- 实际配送时间、承诺配送时间和延迟率如何变化？
- 延迟配送是否与低评分显著相关？
- 哪些地区、品类或商家是延迟问题的主要来源？

## 四、项目边界

- 原始数据没有曝光、点击和加购事件，因此不虚构完整流量转化漏斗。
- 原始数据没有广告花费，因此第一版不计算渠道 ROI。
- GMV 是订单商品成交金额，不包含运费，也不等同于平台收入或利润。
- 数据中的 `customer_id` 是订单级客户标识，跨订单用户识别使用 `customer_unique_id`。
- AI 生成的结论必须能回溯到 SQL、指标定义和查询结果。

## 五、里程碑

1. [x] 数据底座：数据检查、清洗、建模、指标口径。
2. [x] 分析报告：经营、用户、商品、商家、履约五个专题。
3. [x] 分析应用：可交互看板与自然语言取数。
4. [x] Copilot 评估：标准问题集、基准 SQL、错误分类和基线对比。
